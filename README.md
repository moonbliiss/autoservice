# Мастерская

Локальное веб-приложение с тремя ролями и интерактивной 3D-картой цеха. Интерфейс написан на React и TypeScript. Нужен Node.js 24 или новее.

Откройте папку проекта в VS Code и выполните в терминале:

```sh
npm ci
npm start
```

Откройте <http://127.0.0.1:8765/>. Команда `npm start` проверяет типы, собирает интерфейс и запускает сервер. База `data/workshop.sqlite` создаётся при первом запуске. В верхней панели можно выбрать демонстрационного мастера-приёмщика, одного из двух механиков или одного из двух клиентов.

## Автоматическое обновление из GitHub

Остановите уже запущенный сервер клавишами `Ctrl+C`. В папке проекта один раз выполните:

```sh
git switch main
git pull --ff-only
npm run sync
```

Оставьте терминал открытым. Приложение доступно по адресу <http://127.0.0.1:8765/>. Каждые 15 секунд команда проверяет `origin/main`. Когда на GitHub появляется новый коммит, команда подтягивает код, при необходимости устанавливает зависимости, собирает интерфейс и перезапускает сервер. После сообщения «Сборка … готова» достаточно обновить страницу в браузере. Клавиши `Ctrl+C` останавливают сервер и проверку обновлений.

Автоматическое подтягивание работает в чистой ветке `main` и при обновлении без слияния расходящихся веток. При локальных изменениях синхронизация ждёт, пока рабочая копия снова станет чистой. SQLite продолжает использовать файл `data/workshop.sqlite`.

## Структура проекта

```text
client/
  index.html       Общий HTML-шаблон
  src/
    app/           Оболочка, навигация, состояние и синхронизация
    api/           HTTP-запросы и типы ответов API
    features/      Экраны и формы по разделам
    shared/        Общие компоненты, стили и форматирование
server/
  index.js         Запуск сервера и маршруты API
  http/            Сессии, JSON и выдача файлов сборки
  db/              Схема SQLite, транзакции и демонстрационные данные
  workshop/        Чтение и изменение заявок, статусов и остатков
tests/             Тесты бизнес-логики
scripts/           Запуск с автоматическим обновлением из GitHub
```

В `client/src/features/` находятся обзор (`overview`), список и карточка заявки (`requests`), формы действий (`actions`), 3D-карта (`garage`), склад (`inventory`) и автомобили клиента (`vehicles`). Адреса `/` и `/garage-map.html` используют общий HTML-шаблон. React выбирает экран по адресу.

`npm run build` записывает файлы сборки в `dist/`. SQLite хранит рабочие данные в `data/workshop.sqlite`. Обе папки исключены из Git.

## Что видит каждый участник

| Роль | Рабочий экран | Действия |
| --- | --- | --- |
| Мастер-приёмщик | 3D-карта цеха, парковка, заявки, остатки и сроки поставок по заявкам | Оформляет очный визит, принимает автомобиль, назначает пост и механика, переводит автомобиль на парковку и возвращает в цех, фиксирует ответ клиента по смете, регистрирует оплату и выдачу |
| Механик | Назначенные работы, детали к получению, выданные детали и собственные отчёты по прошлым заданиям | Начинает диагностику или ремонт, отправляет результат, время и рекомендации, ставит ремонт на паузу |
| Клиент | Свои автомобили, заявки, указания для визита, статус парковки, смета и оплата | Подаёт заявку, указывает желаемую дату, отменяет её до приёмки, согласует смету или возвращает на пересмотр |
| Запчастист | Потребность в деталях по согласованным сметам, автомобиль и получатель, остатки, поставки и журнал | Выдаёт детали механику, оформляет закупки, принимает поставки и регистрирует приход |
| Управляющий | Все заявки, чьи работы назначены, отчёты, оплаты, склад и справочник | Просматривает рабочие данные всех отделов, назначает и отменяет перегон с парковки |

## Маршрут заказа

1. Клиент отправляет заявку из кабинета, либо приёмщик оформляет её через кнопку **Новая заявка** на обзоре или в журнале. Приёмщик может создать карточки клиента и автомобиля, сразу зарегистрировать приёмку или назначить визит с указаниями, куда заехать.
2. Приёмщик назначает свободные пост и механика и пишет, что проверить и какой результат нужен. Механик возвращает заключение и время диагностики. Пост освобождается. Если диагностика не нужна, смету можно подготовить сразу после приёмки.
3. Приёмщик добавляет услуги, детали и индивидуальные позиции, указывает прогноз готовности и отправляет смету. Клиент отвечает в кабинете, либо приёмщик фиксирует решение, полученное лично или по телефону.
4. Приёмщик назначает задачу, пост и механика. Если ремонт поставлен на паузу, механик может начать другую работу. При переводе на парковку пост и механик освобождаются. После поставки приёмщик или управляющий выбирает припаркованную машину, пост и механика. Пост резервируется, и в кабинете механика появляется задача перегона. Когда механик нажимает **Машина на посту**, парковочное место освобождается и карта показывает переезд. После подтверждения механик может приступить к следующему этапу работы.
5. Приёмщик подтверждает контроль качества или возвращает задачу на доработку. После успешной проверки пост освобождается, клиент видит сообщение о готовности, сумму и историю платежей. Приёмщик может зарегистрировать несколько платежей. Выдача доступна после закрытия согласованной суммы.

## Модель данных

Схема в `server/db/schema.sql` описывает учётные записи, автомобили, заявки и заказ-наряды. Посты и исполнители назначаются заказ-наряду. Смета состоит из версий с сохранённой ценой каждой позиции. Складские движения связаны с поставкой или заказ-нарядом. Оплата ведётся в целых рублях по последней согласованной смете.

Сервер проверяет права выбранной роли при выдаче данных и выполнении операций. Переключатель профилей предназначен для демонстрации на локальном компьютере. Платежи регистрируются вручную, уведомления отображаются в кабинете клиента.

В заявках, оформленных приёмщиком, есть ссылка **Страница статуса для клиента**. По ней можно посмотреть этап работ и парковку без входа. В локальной установке ссылка открывается на компьютере, где работает приложение.

## Склад и поставки

Запчастист открывает **Потребность в деталях** и видит позиции согласованных смет, остаток к выдаче, наличие и ожидаемые поставки. Карточки показывают автомобиль, пост и механика. Закупку можно оформить из нужной позиции или через **Склад и поставки**, если требуется пополнить общий запас.

После фактического поступления запчастист нажимает **Принять поставку** и указывает количество. При частичной приёмке непринятое количество остаётся в ожидаемой поставке. Для назначенного на пост автомобиля запчастист нажимает **Выдать**. Остаток уменьшается, а механик видит выданные детали в своей задаче. Приход и выдача отображаются в журнале движений. Приёмщик проверяет остатки и сроки связанных поставок через склад на 3D-карте.
